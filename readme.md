# LLM 모델 비교·선정 보고서

## 1. 비교 대상
* Gemini 3 Flash (유료)
* Claude Haiku 4.5 (유료)
* GPT-5 mini (유료)

## 2. 사용 환경
* 웹

## 3. 평가 축 및 모델별 점수와 근거

| 평가 축 | 평가 내용 | ① 점수 | ② 점수 | ③ 점수 |
| :--- | :--- | :---: | :---: | :---: |
| **형식 준수성** | 지시한 형식과 제약 조건을 준수했는가? | 5 | 3 | 3 |
| **정확성** | 원문의 날짜, 수치, 참석자명을 누락 또는 왜곡없이 유지하고 있는가? | 5 | 4 | 5 |
| **프롬프트 구조화** | 사용자가 즉시 재사용 가능한 입력 템플릿인가? | 5 | 3 | 4 |
| **예외처리 및 안전장치** | 정보 부족 시 임의 생성을 방지하고 되묻는 질문을 효과적으로 설계했나? | 5 | 4 | 5 |
| **종합 점수** | 최종 점수 (20점 만점) | **20** | **14** | **17** |

### 모델별 평가
* **Gemini 3 Flash**
  지시사항과 출력 형식을 준수하여 수행함. 1~6번 항목 번호를 정확히 매겼음. 입력 템플릿에 중괄호(`{}`)를 사용하여 실무 재사용에 효율적임. 불충분한 정보가 주어졌을 때 사실관계를 왜곡하지 않고 구체적으로 되묻는 예외 처리 능력이 뛰어남.
* **Claude Haiku 4.5**
  기본적인 텍스트 요약은 성실히 수행했으나 회의록 요약본 헤더의 번호를 누락하는 등 출력 형식 지침을 준수하지 않음. 입력 양식을 단순 목록형으로만 제시하여 템플릿으로서의 가치가 낮았음.
* **GPT-5 mini**
  날짜의 요일 오류를 짚어내는 정교한 탐지력을 보임. 요청하지 않은 추가 정보(장소, 일시 등)를 무단으로 작성하여 형식을 흐트러뜨림. 번호가 6~11번으로 밀리는 등 구조적 일관성이 부족했음.

## 4. 결론 - 최종 선정
업무 자동화 모델로 **Gemini 3 Flash**를 채택함.

비즈니스 업무 자동화 시스템은 여러 실무자가 일정한 규격으로 출력물을 공유하고 다른 시스템과 연동해야 하므로 형식 준수가 필수적인데, 이 모델은 다른 모델과 달리 무단 정보 추가나 번호 왜곡 없이 설계 규칙을 모두 이행함. 예외 처리 메커니즘을 가장 안정적으로 수행하였으며 가장 깔끔하고 신뢰도 높은 비즈니스 개조식 톤앤매너를 구사하여 사용자가 즉시 쓸 수 있는 템플릿 구조를 제공함.
